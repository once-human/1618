# Live signals and the history store

The page polls one endpoint, `GET /api/live` (presence + music + a Pinterest version stamp), every
15 s with an ETag; an unchanged answer is an empty 304. Pinterest (`/api/saved`) is refetched only
when its stamp changes. Slower parts poll their own routes: `/api/listening` (10 min),
`/api/timeline` (2 min), `/api/replay` (30 min), `/api/submissions` (1 min).

## Sources

| Signal | Source | Setup | Cache |
| --- | --- | --- | --- |
| Where I am (city), my time, your time | `POST /api/location` from a Shortcut or /admin; Pune by default; browser for your time | `ADMIN_SECRET` | until changed |
| Weather where I am | Open-Meteo (coordinates rounded to ~10 km) | none | 15 min, shared |
| Code activity | GitHub public events (one shared fetch for presence, timeline and sync) + repo `pushed_at` + latest commit | none (optional `GITHUB_TOKEN` raises GitHub's limit from 60 to 5,000 an hour; `GITHUB_WEBHOOK_SECRET`) | 10 min, or instantly via webhook |
| Now playing + tracklist | Last.fm `user.getrecenttracks` | `LASTFM_USER`, `LASTFM_API_KEY` | 10 s edge |
| Covers, links, previews, song length, cover tint | iTunes Search → artist catalog → Deezer + song.link | none | weeks per song |
| On repeat this month, when I listen, streak, new-to-me | Last.fm top tracks/artists (1 month) + last 30 days of plays | as above | 1 h |
| Pinterest profile, boards, mosaics | Profile page data + each board's widget feed | none | 30 min |
| Latest saves | Widget feed + RSS (save times) | none | 10 min |
| Steps, sleep, workouts | Apple Health via an iPhone Shortcut → `POST /api/ingest/health` | Shortcut with `ADMIN_SECRET` | per day |
| My status | iPhone Shortcut → `POST /api/status` | Shortcut with `ADMIN_SECRET` | expires on its own |
| Gone to bed | "Hey Siri, good night" (the *Good Night* Shortcut) → `POST /api/bedtime` | Shortcut with `ADMIN_SECRET` | shown 5 h, kept in history |

Rule: a signal is real or hidden.

## The history store

Neon Postgres (`DATABASE_URL`); schema in `db/schema.sql`. It keeps every scrobble, pin, push,
Health day, plus song lengths for "minutes listened".

**Sync** (`src/lib/history/sync.ts`) pulls only what's new and backfills older Last.fm history 3,000
plays per run until it reaches the first scrobble. It runs:

- whenever someone loads the site (at most every 5 minutes),
- every 15 minutes from GitHub Actions (`.github/workflows/sync.yml`, no secret needed),
- daily from Vercel cron (`/api/cron/daily`, which also cleans up).

**Reading it:** `/api/history?range=week|month|year|all&at=…` or `?from=YYYY-MM-DD&to=YYYY-MM-DD`;
`/api/replay` (year so far); `/api/timeline` (last 48 hours, merged with live sources).

## Going to bed

Saying "Hey Siri, good night" runs the *Good Night* shortcut (Siri runs a shortcut when you say its
name). It records the moment in `kv` (`bedtime`) and as a `sleep` event in the history store. For the
next five hours the Pulse (the live line at the top), /now, Talk and the curl version say "Went to bed at 01:12"
(`src/lib/presence/asleep.ts`). It stops sooner if I'm clearly up: a status set afterwards, or a push
or a pin more than ten minutes after it. Music doesn't end it; I fall asleep to it. "I'm up" on
/admin ends it by hand. The history keeps one bedtime per night (noon to noon), at the last time I
went to bed that night; under ten minutes in bed doesn't count and is dropped. The timeline shows each night, and any stretch on /history shows the usual
time once there are a couple of nights.

## Things only I do

- **`/admin`** (log in with the site key; dark or light, saved with the account so every device opens the same): hide or delete guestbook posts and sent songs, set my status,
  see the store's size and last sync, connect Telegram, get the iPhone shortcuts, run a sync.
- **iPhone shortcuts** (signed, downloadable from /admin; each asks for the site key when added):
  *1618 Health* (today's steps, distance, active calories → `/api/ingest/health`; run it from an
  "App is opened" automation, since Health can't be read while the phone is locked), *1618 Location*
  (city and rounded coordinates → `/api/location`), *1618 Status* (sets or clears the status in the Pulse →
  `/api/status`), *Good Night* (Siri runs it on "Hey Siri, good night": it posts to `/api/bedtime`,
  then gives Siri a good-night line to say). Sources and build steps in `scripts/shortcuts/`: Health
  and Good Night are generated by `build.py` and `goodnight.py`, Location and Status are Cherri
  programs patched by `add-key.py`; all are signed with RoutineHub's
  HubSign and uploaded with a `PUT /api/shortcuts/<name>`.
- **Telegram** for "Talk to me": `TELEGRAM_BOT_TOKEN` in Vercel, then "Connect Telegram" on /admin
  (sets the webhook and claims the chat with a one-time link). Reply to a visitor's message to answer
  them; type without replying to answer the latest chat; `/chats` lists open ones.

## Visitors

- **The visitor log** (`src/lib/visits/`, tables `visits`, `visit_events`, `visit_days`,
  `visit_day_pages`). The page (`Tracker` in the layout, `lib/visits/client.ts`) sends batches to
  `POST /api/track`: pages in order, time on each while visible, scroll depth, links out, and a few
  actions (song sent, guestbook, chat, preview played). The server adds town/country (Vercel geo
  headers) and a device name. A visit is one tab, ending after 30 idle minutes; visits from one
  browser are linked by a random code the browser keeps in localStorage. A visit counts as a
  person once someone moves, scrolls, taps or types; otherwise it's filed as a program ("didn't
  move, scroll or tap"), as are automated browsers. Crawlers, link previews and curl don't run
  JavaScript, so `src/proxy.ts` logs them: its matcher only admits requests whose user agent looks
  like a program (or has none), so people's page loads never touch it. No IP is stored anywhere.
- **Retention**: the daily cron (`foldOld`) folds visits older than 30 days (whole days in India time) into
  `visit_days` (people and visits per country per day) and `visit_day_pages` (views per page), then
  deletes them with their events.
- **Visitors' control**: `/privacy#your-visit` shows everything kept for the browser's code
  (`GET /api/track?me=`), deletes it (`DELETE`, which also blocks late batches from that code for two
  days), and can turn the log off for that browser. Global Privacy Control and Do Not Track turn it
  off too.
- **Admin**: `/admin#privacy` lists visits (24 h / 7 days / 30 days; people, programs or both) with
  each visit's full trail, plus all-time counts by country (`/api/admin/visitors`).

- **Send me a song / guestbook**: `/api/submit`. Songs are re-looked-up on Apple by id. A light
  filter (`src/lib/moderation.ts`, tested) refuses links, slurs, explicit words, ASCII drawings and
  copy-paste spam, lowercases shouting, and replies like a person. Posts that pass go up straight
  away; anything can be hidden from `/admin`. Three posts an hour per visitor.
- **Rate limits** use a salted, one-way hash of the IP that changes daily (`visitorKey` in
  `src/lib/db.ts`); no IP is ever stored.
- **People here** (`src/lib/presence/here.ts`, `roster.ts`, tested): every tab joins one channel on
  Supabase Realtime (a free project used for nothing else). A person is a device: `/api/here`
  hands each tab a daily HMAC of network (IPv6 /64) + OS + physical screen size
  (`src/lib/presence/device.ts`, tested), so tabs, private windows and other browsers on one
  device count once. Trade-off: two people on one network with the same phone model count as
  one. If the code can't be fetched, a per-browser id in local storage is used instead.
  Two signals are merged: each tab broadcasts "hi"/"bye" (seen by others in ~5-400 ms), and the
  server's presence list settles the truth ~2.5 s later and catches tabs that die without a word.
  A reload keeps its tab id, and someone's last tab gets a 1.5 s grace, so reloads never dip.
  Background tabs step out after a minute. No connection, no number. Measured live: arrivals
  50-400 ms, closed tabs <20 ms, closed site 1.5 s, dead machines 1.5-4 s. Free plan: 200 open
  tabs at once; past that, extra tabs show no count. `presence/` holds a tested self-hosted
  alternative (one Bun file) for if that's ever outgrown.
- **Visitors**: each person once a day (`visitors` table of daily hashes); hashes are kept for the
  calendar month (for the map); the nightly job folds earlier months into one number and deletes them.
- **🔥**: a count per song, one per visitor per song every 10 minutes.
- **Talk to me** (`/talk`, `/api/talk`, `/api/talk/cli`, `/api/telegram`, `src/lib/talk/`): one chat
  per browser, under a name or anonymous (everyone is asked first; a new name starts a fresh chat).
  Messages are kept and sent to my bot with the name, town, device and page; my replies (from
  Telegram or /admin) are pushed to that visitor over a realtime channel only their browser knows
  (~0.5 s), with a 20 s poll as backup. A chat is a 128-bit code: the only key to it. Visitors can
  open it elsewhere with its link or delete it (my Telegram copies stay). Terminal:
  `curl -L -d "text=hi&name=Ana" onkaryaglewad.in/talk`, then `curl -L onkaryaglewad.in/talk/<code>`.
  Against floods (`src/lib/talk/server.ts`): at most 5 in a row until I reply; no new chat while 5
  are waiting from that network, and at most 10 unanswered across its chats; 3 new chats an hour and
  6 a day per network; 20 messages per 10 minutes, or 120 once I've replied in the last 2 hours;
  the same message twice within 30 s is dropped. Each chat keeps salted one-way codes for its
  network and device (never the address), so `/block` (Telegram) or Block (/admin) shuts out that
  network until unblocked.
- **/admin**: login with the site key (a 30-day HttpOnly, SameSite=Strict cookie signed with it;
  5 tries per network per 15 minutes; origin-checked; "log out everywhere"). Shows who's on the
  site and where, chats (read/unread, replies, block, delete), posts, status, place (search, recent,
  "where I am now", hold), health, sources, Telegram, shortcuts with QR codes, recent logins.
- **Who's here and where**: towns come from Vercel's IP headers (city level), travel with presence,
  and read as "you, two people in Berlin and someone in Mumbai" (`words.ts`, tested). Scroll
  positions are broadcast at most once a second while 2-8 people are on the site, for the dots.
- **This month's map** (`/api/visitors/month`, /now): towns of this month's visits (from the 1st, India time),
  coordinates rounded to ~10 km, deleted when the month ends with the hashes. Land is a 2 KB dot grid from `scripts/make-land.mjs`.
- **Played your song**: the sender's browser keeps a random code (stored scrambled with the
  submission); `/api/songs/mine` matches their songs against later plays by song key.
- **Built to this soundtrack** (`src/lib/history/soundtrack.ts`): a project's commits since my
  listening history began, grouped into sittings (`sessions.ts`, tested), against what played.
- **Sky on /now** (`src/lib/sky.ts`, tested for contrast at every 5 minutes in any weather).
- **`curl -L onkaryaglewad.in`**: terminal clients get `/api/curl` (rewrite in `next.config.ts`).
- **Bots don't count** (`src/lib/bots.ts`, tested): crawlers, link previewers and automated or
  headless browsers are left out of who's here, the visitor count and today's map, and a visit only
  counts after a person moves, touches, scrolls or types.
- **Sent with the page**: each page streams a cached snapshot of its live data (`src/lib/seed.ts`,
  `<Seed>`), so it shows as soon as the page starts rather than after another request.

## Limits worth knowing

- **Paused vs playing, and song position.** Neither Apple Music nor Last.fm reports them. The start
  is estimated (previous scrobble + its length, or when the site first saw the song), and a song still
  "playing" a minute past its length is shown as last played.
- **Minutes listened** are estimated from known song lengths; unknown ones count as 3½ minutes. The
  share of real lengths grows as the sync looks them up.
- **Pinterest**: public pages embed 10 boards and no monthly views; the official API (planned)
  would give all boards.
- **Apple Health** has no web API, hence the Shortcut.
- **Vercel's free plan** runs cron once a day; GitHub Actions and visits keep the store fresh in
  between.

## The laptop (desk agent)

A small agent on my Arch/Hyprland laptop (github.com/once-human/desk-agent) posts a sample about once a minute to `POST /api/ingest/desk` (Bearer site key). A sample is: active or idle, the focused app (name and category, never a window title), the browser's site (host name only), the repo, whether Claude Code is working, and what's playing.

- Window titles never leave the laptop. YouTube is only "Watching YouTube" with a count of videos; browser media titles are dropped on the laptop and again in `src/lib/desk/model.ts`. Music players (Spotify and the like) show the track. Adult sites collapse to "Browsing".
- The newest sample is the live state (`kv desk:last`, `GET /api/desk`). The laptop counts as online for 4 minutes after its last sample; after that the site says "last seen", it never guesses.
- Samples are kept 7 days (`desk_samples`), folded into spans on read (`GET /api/desk/days`), and the daily cron rolls older days into `desk_days` totals.
- "Good Morning" (`scripts/shortcuts/goodmorning.py`) ends the night's bedtime, which stamps the wake time.
